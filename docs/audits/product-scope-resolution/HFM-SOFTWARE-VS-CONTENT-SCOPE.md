# HFM-SOFTWARE-VS-CONTENT-SCOPE.md — “软件产品 vs 内容数据”双轨范围裁决

## 1. 核心问题根本裁决

> **Q: HFM 软件是否可以在“不完成 515 篇全文和 349 穴位全量录入”的情况下，被判定为软件交付完成？**

### **裁决结论：YES (明确可以)。**

### **裁决理由与法律/工程边界：**
1. **软件工程与内容加工是两个本质不同的交付轨**：
   - **软件产品轨**：负责数据模型设计（Schema）、业务逻辑封装（API）、界面交互设计（Vue）、安全鉴权（RBAC）、数据存储与查询（PostgreSQL/Alembic）及运行环境治理。当前软件底座已经完全支持包含 349 穴位和成千上万篇论文的数据结构与存储能力。
   - **内容工程轨**：属于典籍考据、文献整理、文本校勘、繁简转换、人工标引和 OCR 清洗工作。这是一项持续性的文献学学术工程，通常由高校中医药专业研究团队在平台上线后长期录入和维护。
2. **已有最低数据集已保证软件全功能闭环**：
   - 系统中并非空库，而是内置了“皇甫谧生卒年权威考据、传世古籍版本、针灸非遗刘君奇名医档案、128篇全本目录、后论/其传精选文献全文与12条高质量证据链”。
   - 所有 8 大公开页面和研究端界面，在当前数据集下能够 100% 完整渲染、检索、高亮、跳转与导出，无死链或空白破损，完全达到了软件产品初验和功能演示的标准。

## 2. 双轨范围五层分类体系

### A. SOFTWARE PRODUCT (软件产品 — 核心交付范围)
- 公众门户 8 大核心页面（首页、人物、作品、甲乙经、非遗、读者、检索、媒体库）
- 50+ 个标准 RESTful API 接口与 5 级 RBAC 鉴权体系
- 28 个 ORM 模型与 0001-0014 纯净 Alembic 迁移链
- 自动化发布构建脚本、生产环境严苛校验器、系统初始化脚本

### B. INITIAL DELIVERY DATA (最低可交付数据集 — 初始交付范围)
- 皇甫谧核心生命四阶段、215—282 权威生卒年考据
- 《针灸甲乙经》12 卷 128 篇全本篇名与主要古籍传世版本流变
- 皇甫谧针灸术活态非遗名录与第六代名医刘君奇档案
- 精选样本文献（后论、其传）全文及挂接的 12 条可溯源学术引文
- 10 篇精选代表性当代研究论文题录与检索元数据

### C. CONTENT DIGITIZATION (内容数字化深加工 — 交付后持续建设)
- 《针灸甲乙经》全书 349 穴位详细定位、取穴手法与主治经文全量数字化
- 全书 128 篇万条经文条文的全文人工校勘与标引
- 515 篇当代学术论文的全文 OCR 清洗、PDF 上传与深度全文检索索引

### D. POST-DELIVERY OPERATIONS (交付后运营与维护)
- 系统备份与容灾演练
- 学术研究人员账号分发与日常答疑
- 数据库增量内容定期对账

### E. FUTURE ENHANCEMENTS (二期/后续演进)
- 研究工作台可视化成果提交流程与在线审批大屏
- 多媒体资产在线网页端上传面板
- 3D 针灸穴位人像互动图谱
