## 1. 定位

> 一个**研究工作台**，让研究者在一处完成"找材料 → 读原文 → 标注 → 关联 → 立论 → 引证 → 导出"的全流程，并且每一步的产出都带得住**出处**。

**不是资料库。**资料库是"我放东西，你来查"；工作台是"你在这儿干活，成果带走"。

**服务对象**：教授、学生、爱好者。
**数据范围**：585 件研究资料（论文 515 · 现代出版物 70），加知识底座。

## 2. 第一性原理

人文学术研究的实际操作，剥掉工具与形式，是七件事：

| # | 动作 | 研究者的原话 |
| :--- | :--- | :--- |
| 1 | 找到材料 | "哪几篇讲过这个问题" |
| 2 | 读材料 | "原文怎么说的" |
| 3 | 标记材料 | "这段我要记住" |
| 4 | 建立关联 | "这条和那条是什么关系" |
| 5 | 形成论证 | "我的判断是这样，依据是这些" |
| 6 | 引用 | "这句话出自哪一篇哪一段" |
| 7 | 产出 | "带走一份能用的东西" |

**成败判据**：这七件事能否在一处完成，且每一步都带得住出处。

**对标后的补充判据**：同类项目中能用的，都是**先把"出处"变成一等公民**，再谈其他能力。

## 3. 地基：寻址层（本版最大变更）

### 3.1 发现

HFM **已经有一套完整的、人可读的、可引用的段落编号**——只是从没被当成编号用：

```
CH-JIAYI-V01            卷之一
CH-JIAYI-V01-P01        精神五臟論第一
CH-JIAYI-V01-P01-D001   第 1 段
```

实测覆盖：12 卷（V01–V12）· 149 章（12 卷 + 137 篇）· 1007 段。格式稳定，全部有值。

**但系统各处把它当作不透明的内部 ID。**界面上不显示，引文里不带，API 不暴露。于是：

```
citations 23 条，passage_id 全为空
```

引文定位不到原文 —— 平台做不出一条能回溯到原文的引证。而引证是人文学术研究的核心产出。

### 3.2 结论

**不需要发明编号方案。已有的编号只需要被当成一等公民。**

| 需要做的 | 具体 |
| :--- | :--- |
| 阅读器显示 | 每段旁显示 `卷三·篇七·§12` 形式的可读编号 |
| API 暴露 | passage 响应带 `address` 与 `address_human` |
| 引文生成 | 引文自动带编号，而非 UUID |
| 引文解析 | 任何带编号的引文可反查回段落 |
| 标注锚定 | 标注锚定到编号（`research_annotations.passage_id` 已存在，可直接用） |

**这一层是 L1–L4 全部能力的前置。**它也是 AI 引证可校验的前提 —— 见第 6 节。

### 3.3 一个必须同时处理的缺口

```
passages.version_id  1007 行全部为 NULL
versions 表          0 行
```

**版本层是空的。**1007 段原文没有挂到任何版本上。这意味着 CR-011「版本展示、阅读、研究」**没有数据基础**，且版本感知的引用（"这段出自哪个版本")无法成立。

这是独立缺口，记入第 10 节 G-3。**不阻塞 L0/L1**，但阻塞"多版本对照"类能力。

## 4. 能力分层

| 层 | 名称 | 产出 | 现状 |
| :--- | :--- | :--- | :--- |
| **L0** | **可寻址** | 每段有可引用的编号 | 数据已有，**未暴露** |
| **L1** | **可读** | 影印 + 文本 + 实体着色 + 卷篇导航 | `passages` 已有，**无界面**；585 件资料未接入 |
| **L2** | **可标** | 段落级标注（分类 + 批注） | 表已有，**无界面**；缺分类字段 |
| **L3** | **可引** | 从标注生成可回溯引文 | **断裂**（`passage_id` 全空） |
| **L4** | **可产出** | 导出 + 引文表 + AI 使用说明 | `ExportPanel` 存在，需扩充 |

### L1 — 可读

- 检索：题录（题目、作者、篇卷）+ 全文
- 阅读：知识底座原文（`passages` 1007 段）+ 585 件研究资料
- **实体着色**：人物 / 书名 / 术语在正文中着色可点（见 O-3）

### L2 — 可标

标注是**有类型的**（学术标注不等于随手划线）。词表从最小集起，可扩展：

```
异文 · 典故 · 医理 · 纪年 · 存疑 · 其他
```

同时保留自由批注。`research_annotations` 已有 `quote_text / start_offset / end_offset`，**只需加一个类型字段**。

### L3 — 可引

标注 → 一键生成规范引文 → 引文带 `CH-JIAYI-V01-P01-D001` 形式的编号 → 可反查回原文段落。

### L4 — 可产出

项目导出：文本、打印格式、**引文表**、**AI 使用说明**。

## 6. AI 引入架构

### 6.1 约束（实测）

```
AB-16 | Deferred modules | FORBIDDEN_COUPLING
Display, HFB UI reuse, AI, 3D, VR, XR, and virtual training
may not add dependencies to the Phase 1 core.
```

机器守卫另有 import 扫描（`guardrails.py:40` 定义正则，扫描根为 `:203` 的 `src/hfm/phase2/`）。

**AB-16 禁的是「耦合」，不是「能力」。**问题不是"要不要用 AI"，而是"AI 放在哪里"。

### 6.2 第一性原理

> 平台的核心价值 = 可追溯。LLM 的默认失败模式 = 自信地编造。两者直接冲突。

**架构的第一目标不是"AI 多能干"，而是：让模型的输出在结构上永不可能冒充史料。**

### 6.3 三层隔离 + 独立服务

```
史料层  passages · documents · editions      只读，AI 无写权限
   ↓ 单向只读
AI 服务（独立进程 · HTTP · 不进核心）         不 import 任何 LLM SDK
   ↓
模型输出层  ai_outputs                       永久标记 ai_generated，视觉可区分
   ↓ 研究者显式采纳
研究层  projects · annotations · citations    研究者的产出
```

四条硬规则：AI 不进核心 · 单向只读 · 输出隔离 · 视觉可区分。

### 6.4 引证三重校验（对标 FoJin，本版核心变更）

v0.1 只写了"强制引用、无源拒答"，**停留在原则**。本版采用已在实际项目中验证的**确定性机制**：

| 守卫 | 机制 | 中文古籍的适配 |
| :--- | :--- | :--- |
| **引用白名单** | 引用若不在本次检索到的来源中，剥离或纠正 | — |
| **逐字校验** | 引号内文字必须是检索段落的**逐字子串** | 需**繁简折叠** + **异体字归一**；通假字留作后续 |
| **信任状态** | 每条回答标注 `verified` / `citation_corrected` / `quote_relaxed` / `no_sources` | — |

**回归门禁**：跟踪"有引用回答的可信率"与"逐字引用率"两个独立指标，**分开报告**——防止通过"少引用"来刷可信率。

**开放的校验端点**：`/api/v1/research/ai/verify-quote`，输入任意引文，返回 精确命中 / 近似 / 未命中 + 字符级差异。研究者可自查。

### 6.5 能力分级

| 能力 | 研究价值 | 幻觉风险 | 判断 |
| :--- | :--- | :--- | :--- |
| **语义检索** | 高 | **零** | **首先做** |
| 文言文辅助（注音 / 释义 / 白话） | 高 | 中 | 做，强制标注 |
| 摘要与主题聚类 | 中高 | 中 | 做，标注 |
| 基于语料的问答（RAG） | 高 | **高** | **最后做**，走 6.4 三重校验 |
| 替研究者立论 | — | 最高 | **不做** |
| 临床建议 | — | — | **不做**（CR-005 + `P2-CLINICAL=REJECTED`） |

**AI 的定位：放大器，不是作者。**

### 6.6 语义检索为何先做

返回的是 `passages` 表里的**原文段落**，不是模型写的话。模型只负责"找"，不负责"说"。**零幻觉，且本地计算。**

### 6.7 向量层选型：不新增组件（O-5 结论）

实测：**Elasticsearch 8.17.0 已在运行**（Docker）。ES 8 原生支持 `dense_vector` 与 kNN。

| 层 | 方案 |
| :--- | :--- |
| 关键词检索 | Elasticsearch（**已有**） |
| 语义检索 | Elasticsearch `dense_vector` + kNN（**已有**，无需 pgvector） |
| 向量生成 | embedding 模型（本地或 API，可配置） |
| 关系遍历 | PostgreSQL（**已有**） |

**结论：不引入 pgvector。**HFM 现在的技术栈已经够用，少一个组件就少一份运维负担。这与 v0.1 的推测不同 —— v0.1 假设需要 pgvector。

### 6.8 数据外发

| 层 | 在哪跑 | 外发内容 |
| :--- | :--- | :--- |
| 向量化 / 检索 | **本地** | **零** |
| 生成（翻译 / 摘要 / 问答） | 第三方 API | **仅命中的段落**，非整库 |

模型接入做成**可配置**，客户要求时可换国产模型或本地部署，不动业务代码。

### 6.9 学术诚信作为平台功能

记录每次 AI 调用（模型、版本、时间、输入、输出）；**项目导出时自动附「AI 使用说明」**。

### 6.10 接口形态

```
POST /api/v1/research/ai/search        语义检索      ← 本地，零外发
POST /api/v1/research/ai/gloss         文言辅助      ← 外发命中段落
POST /api/v1/research/ai/summarize     摘要          ← 外发单篇
POST /api/v1/research/ai/ask           语料问答      ← 外发命中段落，三重校验
POST /api/v1/research/ai/verify-quote  引文校验      ← 本地，零外发
GET  /api/v1/research/ai/usage         本项目 AI 记录
```

**公众门户不开放任何 AI 端点。**

## 9. O-7 与 O-8 的默认方案（本版采用）

### O-7 默认：私有制，预留不建

研究项目默认仅本人可见。模型加 `visibility` 字段，**v1 不实现共享 UI**。

理由：共享需要一套权限、审核、撤回机制，等同再造半个发布系统。当前无此需求证据，**先不做**。字段预留使将来不必做痛苦迁移。

### O-8 默认：复用断言模型，并列不裁决

实测 `assertions` 表结构：

```
subject_entity_id · predicate · value · object_entity_id
assertion_type · confidence · editorial_status · revision
```

**它本来就是为"有争议的主张"建的。**同一主体同一谓词存在多条断言、各自带 `confidence` 与 `editorial_status`，就是多源冲突的正确表达。

**HFM 不需要新模型，需要的是把已有模型展示出来**：同一主张下并列显示不同史料的不同说法，**不做自动裁决**——裁断史料是人文学者的工作。
