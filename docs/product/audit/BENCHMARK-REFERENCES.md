## B-1 FoJin 佛津 — 采纳度最高

| 项 | 值 |
| :--- | :--- |
| 仓库 | https://github.com/xr843/fojin |
| 许可 | Apache 2.0（仅源码） |
| 成熟度 | 2,096 commits · 341 stars · 63 forks |
| 技术栈 | FastAPI + PostgreSQL 15 + pgvector(HNSW) + Elasticsearch 8 + Redis 7 + React 18 |

**关键事实** `[外部来源]`：

- RAG over 670K+ 向量，BGE-M3 embedding，HNSW 索引
- 三道**确定性**引证守卫：
  1. **引用白名单** —— 引用若不在本次实际检索到的来源中，被剥离或纠正
  2. **逐字校验** —— 引号内文字必须是检索段落的逐字子串（繁简折叠），非逐字者降级为普通叙述
  3. **信任状态** —— 每条回答标注 `verified` / `citation_corrected` / `quote_relaxed` / `no_sources`
- 回归门禁：`served_trustworthy_rate` 与 `verbatim_quote_rate` **分列报告**，防止靠"少引用"刷分
- 公开端点 `/api/verify/quote`，对任意引文做字符级差异校验
- 规模：10,500+ 文献 · 110K+ 实体 · 28,000 关系

**HFM 采纳了**：宪章 §6.4 的引证三重校验与回归门禁设计。**未采纳**其语料规模、图谱、多语言对照等。

> **审计注意**：FoJin 的守卫针对**佛典**（多语言、有平行文本）。HFM 是**中文文言文**。适配差异是 Q2 的核心。送审方**未验证** FoJin 的实际误判率，只核实了其机制设计。

## 采纳记录的审计要求

审计方须检验：

1. **每条"采纳"是否有据** —— 被采纳的设计在对标项目中是否真实存在（可访问仓库页核实）
2. **是否过度采纳** —— 是否引入了与 HFM 目标不符的复杂度
3. **是否采纳不足** —— 对标项目中是否有 HFM 明显需要却未采纳的能力
4. **是否有误读** —— 送审方的转述与来源项目实际设计是否有偏差

**特别提请**：B-1 与 B-2 的关键事实均为 `[外部来源]`，送审方**未运行验证**。审计方如认为必要，应独立核实其源码。
