## 0. 为什么需要这份契约

2026-09-14 核查发现：**前端的内容架构从未被严肃规划过。**

事实：

1. 首页 8 个 section **100% 由前端静态 TypeScript 投影 (`src/data/*.ts`) 驱动**，渲染时不发任何后端请求（`HFM-HOMEPAGE-RUNTIME-MAP.md` 实测，`API_BACKED_SECTIONS = 0`）；后端只贡献了「四域探索」卡片一行装饰性数字。
2. 数据库已入库 **675 文献 / 91 版本 / 1156 篇章段落 / 69 非遗 / 681 媒体**，首页**一个都没用**。
3. `HFM-GAP-MAP.md` 已把这条列为 **P1 缺口 GAP-02**（"运营在库里改数据，首页不动，须重新编译前端发布"）。
4. `HFM-INFORMATION-ARCHITECTURE.md` §3 规划首页为 **六段叙事**（HERO / 人物 / 其言 / 甲乙经 / 传承 / 政校共建），对齐客户强制 5 链接；**实际首页是另一套 8 区**（一生 / 一部书 / 知识对象 / 史料证据 / …），**且这 8 区的规格没有任何设计文档**——全库搜索 `CF-07/CF-08/CF-09` 只命中代码与测试（`homeProjection.ts` / `HomeView.vue` / `ui03_home.spec.ts` / `ui03-home.spec.ts`）。
5. 前端治理是空白：`docs/design/*` 全部标注 `DESIGN INPUT`（非治理文档），没有任何裁决前端内容变更的机制。

**结论**：首页"展示什么"既无文档、又绕开数据管线。在补上这一层之前，任何 UI 精修都是在沙子上盖房。

## 2. 内容主权原则（三条铁律）

> **R1 — 单一真相源（SINGLE SOURCE OF TRUTH）**
> 平台的**内容真相在数据库**，经由既有的内容准入 + 发布管线（`ContentArtifact` → `PublicationRecord` → `PUBLISHED`）产出。**前端不承载内容真相。**

> **R2 — 前端只渲染（RENDER, DON'T STORE）**
> 前端的职责是**投影（presentation）**，不是内容仓库。前端消费 `/api/v1/public/*` 的已发布投影；任何前端硬编码的内容常量，**要么是呈现层配置（标签/顺序/图标），要么必须显式标注为降级兜底**。

> **R3 — 空态诚实（HONEST EMPTINESS）**
> 数据未发布 / 未就绪时，前端显示**诚实的空态或不可用态**，**绝不**用静态常量长期顶替可发布数据。（这条不禁止降级兜底，但禁止没有"降级"标签的静默顶替。）

**推论**：首页要从"客户材料登记册"变为"平台知识库的入口"。为此必须先补齐**内容发布**（§6 补课项）——不是先把前端写满静态数据。

## 3. 数据源分级（T0 / T1 / T2）

| 级 | 定义 | 允许用途 | 标注要求 |
| :--- | :--- | :--- | :--- |
| **T0 — 已发布公共投影** | `/api/v1/public/*` 返回的 `PUBLISHED` 数据 | **首页与全站默认内容源** | 必须标注 `data-source="backend"` |
| **T1 — 客户授权素材投影** | `src/data/*.ts` 中**可追溯到客户素材**的静态投影（`hfmzl/`、`zzcl/`、docx） | **仅作降级兜底**：后端不可达 / 数据未发布时的兜底呈现 | 必须标注 `data-source="fallback"` + 可见的"离线/兜底"提示 |
| **T2 — 禁止** | 虚构内容、推断的版本关系、内部路径（`hfmzl/`、`zzcl/`、`registerKey`）、临床话术 | **一律禁止** | — |

> 现行 `useHomePublicData` 已有 `source: 'backend' | 'fallback'` 与 `data-home-source`，**机制正确，沿用**；本契约把它从"首页一处"升为**全站不变量**。

### 4.1 铁律：一段一职责

> **首页每一段只回答一个问题，同一事实不得在首页出现两次。**

这条是 2026-09-16 版式重构的直接结论。此前首页各段普遍承载三到五样内容，
且同一事实在多段重复陈述，读者的第一感受是"太多、重复"：

| 曾经重复的事实 | 曾出现在 |
| :--- | :--- |
| 皇甫谧的定义 | 首屏 **与** 人物段页眉 |
| 《针灸甲乙经》 | 首屏展板、四入口带、甲乙经段，**三处** |
| 版本文数、篇章数 | 甲乙经段的登记行 **与** 统计带 |
| 活态传承台账 | 非遗段的六行登记 **与** 三张材料卡 |
| 通往同一页的链接 | 非遗段三张卡 **与** 一个按钮，**四个入口** |

**判据**：某段若删掉其中一样，该段要回答的问题仍然答得完整 —— 那样就是多余的。
