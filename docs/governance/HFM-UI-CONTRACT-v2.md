## 0. 为什么重建

本次审计（2026-09-16）的结论：旧的 UI 文档体系已经把一次**视觉重构**变成了**逐段硬清单**，与参考图正面冲突。冲突点如下，全部废止。

| 旧文档 | 它规定的事 | 为什么阻碍重构 |
| :--- | :--- | :--- |
| 内容契约 v1 §4 / §4.2 | 首页区块数固定 5+1，逐段列明"展示什么、在哪、来自哪"，且**这是一份清单，不是建议** | 参考图的首页是另一套段落与节奏，逐段清单直接冲突 |
| 内容契约 v1 §4.1 | 一段一职责铁律 + 判据 | 同上；且判据是给旧版式写的 |
| 内容契约 v1 §2 R1–R3 / §3 | 数据库是唯一真相源、前端只渲染、T0/T1/T2 分级强制、`data-source` 必标 | 与已认可的门户定位（编辑型内容站）互斥，见 §4 |
| 内容契约 v1 §6 / §7 | 内容结构变更必须先改契约再改代码；验收 5 条 | 重构期间每改一版都要先改契约，等于锁死 |
| 内容契约 v1 §9 | 两条下限：首屏必须含真实计数、人物段不得少于 10 条 | 把版式选择写成了验收线 |
| UI-FREEZE-CANDIDATE / FINAL-ACCEPTANCE-ARCHIVE | `FROZEN`，冻结 2026-09-01 的浅色八段首页 | 冻结的是一个已被推翻的版本 |
| UI-OPTIMIZATION-DAG | UI-00…UI-15 的固定顺序与每 WP 的 visual acceptance | 全部按浅色纸面方向写的 |
| HFM-VISUAL-DIRECTION | 混合方向 + "暖白 / 墨色 / 低饱和朱砂" | 参考图是相反的深色展厅（已重写，见 v2） |
| HFM-DESIGN-TOKENS-PROPOSAL | CANDIDATE 候选值，未评审不得写入代码 | 值已按 UI-01 落盘并被方案六覆盖（已重写，见 v2） |
| 依赖测试 | `ui03-home.spec.ts` 固定 6 个 section id 与 H2 字面量、人物段 ≥10 条；`ui02_shell.spec.ts` 固定主导航长度 = 5 | 把旧版式写成断言，重构即红 |

**结论**：v1 契约的实质内容——5+1 区块、T0 强制、逐段清单、变更前置审批、两条下限——全部不再有效。仅其中"不虚构内容"与"隐私分级"两条被本契约以改写形式继承（§4）。

## 1. 视觉基准

**方向：方案六 · 沉浸体验 · 未来展厅**（`HFM-UI-CK.PNG` 右下格）。替代此前的浅色纸面方向。

| 要素 | 基准 |
| :--- | :--- |
| 画布 | 深色。近黑但偏墨绿，**非纯黑**；抬起面 / 展板面层层向上 |
| 文字 | 暖白，非纯白；三级层次（主 / 次 / 元数据） |
| 强调色 | **仅一种**：青铜色。用于刻度、序号、当前导航、细线强调 |
| 分隔 | 大留白 + 发丝线。**不用卡片投影、不用圆角块分栏** |
| 光感 | 光从上方来，极弱顶光只作方向感 |
| 字体角色 | 沿用现有六个角色（`sans` / `serif` / `display` / `heading` / `ancient` / `numeric`） |
| 图像 | **全站真实影像**：雕像、展厅、古籍书叶、客户实拍。不用插画、不用图库占位 |
| 中英并置 | 每个段落带一个英文小标（`HUANGFU MI AND THE CLASSICS` 式），与中文标题同段 |

**禁止**（方案的负向定义，从 `HFM-UI-CK.PNG` 与 `HFM-DESIGN-PRINCIPLES` P3 继承）：仿古网站、国潮电商、政府红模板、高校蓝模板、SaaS Dashboard、卷轴 / 宣纸背景 / 祥云回纹 / 廉价水墨 / 金龙宫廷风。

**现行落点**：公众门户**整站**是深色展厅面 —— 由 `apps/frontend/src/layouts/PublicLayout.vue` 在壳层换掉语义色 token（`data-surface="exhibition"`），页头、页脚与所有页面一次性跟着变。研究端与后台用各自的 layout，不受影响。

**待办**：仍有页面保留了旧版式的内部结构（`/jiayi`、`/heritage`、`/yan`、`/search`、`/library`、`/archive`、阅读器）—— 它们已在深色画布上可读、可访问（axe 矩阵通过），但尚未按参考图重排版式。

## 4. 内容来源与分层

门户是**编辑型内容站**（依据 `HFM-PUBLIC-PORTAL-CHARTER-v1.md` 与 `HFM-PUBLIC-PORTAL-EXECUTION-PLAN-v1.md`）。分三层，来源自由，不再强制每段绑后端：

| 层 | 位置 | 用途 |
| :--- | :--- | :--- |
| ① 静态叙事层 | `apps/frontend/src/data/*.ts` | 标题、正文、引言、卡片文案、段落顺序。编辑可控，改内容 = 改文件 + 重建 |
| ② 受控资产层 | 公开 API `/api/v1/public/media/*` | 实物影像（影印、证书、照片、视频）。受 `access_scope` 约束 |
| ③ live 计数 | 公开 API `/api/v1/public/*` | 首页与栏目页的数字指标。取不到时按 §5 降级 |

**v1 契约废除的条款**：R1 单一真相源、R2 前端只渲染、T0/T1/T2 分级强制、`data-source` 必标、每段至少一条 T0、变更前置审批。**全部不再有效。**

**仍然有效（不可破）**：

1. **不虚构**（原 T2）：不编造史实、不推断版本关系、不生成不存在的内容。库中没有的，页面上如实留白或用编辑文案，**不得伪造**。
2. **不暴露内部路径**：`hfmzl/`、`zzcl/`、`registerKey` 等内部标识不出现在任何页面上。
3. **隐私分级**：`HFM-ASSET-PRESENTATION-POLICY.md` 的 P0–P3 仍然有效 —— P2 须脱敏，P3 不进入公共投影。这一点独立于视觉重构。

---

## 5. 不可破底线（重构期间同样不可破）

1. 每页**唯一 H1**。
2. 所有 `<img>` 有 `alt`；装饰性影像 `alt=""`。
3. 键盘可达、焦点恒可见、抽屉有 Esc 与焦点返回。
4. `375 / 768 / 1440` 无横向溢出。
5. axe 无阻断级违规；深色画布上正文对比度 ≥ 4.5:1。
6. 数字指标取不到时**降级为不显示或编辑文案**，不显示 0，不编造。
7. 检索入口在全站唯一且可用。
8. 不新增 UI 框架、动画库、图标库；沿用现有 token 与原生 CSS / SVG。
9. `prefers-reduced-motion` 下功能等价。

## 6. 变更规则与验收

**改版式、改组件、改段落顺序、改文案、换影像 —— 直接改，不需要改本契约。**

只有在以下四种情况才需要修订本契约：

1. 视觉基准变化（§1）；
2. 主导航或信息架构变化（§2）；
3. 页型骨架出现新的页型或段落数量变化（§3）；
4. 内容来源分层变化（§4）。

**验收**：`pnpm typecheck` · `pnpm lint` · `pnpm vitest run` · `pnpm e2e` 全绿，加 §5 逐条自检。
